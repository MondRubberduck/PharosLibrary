# Pharos pipeline — the optional engine chains

Everything here is optional: Pharos searches, measures and serves without
it. These chains add what only an engine can produce: Unreal packs as FBX
with engine-exact material recipes, Blender kits as FBX, Blender-measured
records of `.blend` containers. Each reads the same `pharos_config.json`
as the app (`PHAROS_CONFIG` overrides the path); the shell drivers take
`ASSETS_ROOT`, `UE_EXE` and `BLENDER_EXE` as environment variables.

`pharos.py convert` and `extract` run these chains for the folders the
library map says yes to, and refuse the rest. The commands below are
what they run.

**Safety rule:** source libraries are read-only. Conversion works on a
disposable sandbox copy; outputs land in `<pack>/Exports/`.

## 1. `conversion/` — Unreal `.uasset` packs → FBX + textures + manifest

Requires Unreal Editor 5.x (command line) and Git Bash, on Windows;
Blender for the optional round-trip check. About 1–30 minutes per pack.

| Tool | What it does |
|---|---|
| `convert_packs.sh` | the driver: one pack → `Exports/{FBX,Textures}/` + `manifest.json` (discovery, sandbox sync, engine export, verify, Blender round-trip, status) |
| `export_pack.py` | runs inside UnrealEditor (job JSON in `AMCONV_JOB`) |
| `relink_pack.sh` + `relink_materials.py` | rewires materials with engine-exact texture parameters → manifest v2 (`--preview` dry-runs on a copy) |
| `verify_pack_export.py` | independent check without an engine: every manifest link, FBX header, texture dimensions |
| `pack_discovery.py` | filesystem-only pack and content-root discovery |
| `batch_packs.sh` | batch driver over a pack root (resume, skip-if-done, failure isolation) |

```bash
export UE_EXE="/c/Program Files/Epic Games/UE_5.7/Engine/Binaries/Win64/UnrealEditor-Cmd.exe"
export ASSETS_ROOT="D:/path/to/packs"          # children = packs
cd pipeline/conversion
python make_sandbox.py                         # once: the local conversion sandbox
bash ./convert_packs.sh --pack "MyPack"        # --skip-meshes NAME for exporter-crashing assets
bash ./relink_pack.sh --pack "MyPack" --preview # engine-exact wiring, dry run
bash ./relink_pack.sh --pack "MyPack"           # apply: manifest v2 = recipes
python verify_pack_export.py "<pack>/Exports"  # must print PASS
cd ../.. && python pharos.py ingest            # imports the pack and its recipes
```

The manifest schema is `pharos.pack.export/v2` (v1 imports the meshes
without recipes until the relink runs; legacy `kiosk.*` ids are read).
The sandbox (`sandbox/Sandbox.uproject`) is not in the repo: an empty
throwaway UE project matching your engine version, generated by
`make_sandbox.py` (version from `UE_EXE`, or `--engine-version 5.7`);
packs are copied into it for the headless run. Delete and regenerate
any time.

## 2. `kitbash/` — KitBash-style `.blend` kits → per-assembly FBX

Requires Blender. One FBX per root assembly (`*_grp`), textures resolved
by file name, `kit_manifest.json` per kit.

```bash
cd pipeline/kitbash
python export_all_kb3d.py            # both kit layouts (.blender.native, or .blend in the kit root)
python run_kb3d_metadata.py          # material names + textures (needed for recipes)
cd ../.. && python pharos.py ingest  # builds _Agent_Files/kb3d_models.jsonl and imports
```

Blender is found through `BLENDER_EXE`, then PATH, then the newest
install. The kits root is `kitbash_root` in the config or
`PHAROS_KB3D_ROOT`. `PHAROS_MAP_FOLDERS` (library-relative folders,
`os.pathsep`-separated) limits chains 2 and 3 to those folders;
`pharos.py extract` sets it from the map. One Blender process per file:
the threaded FBX importer crashes when batched.

## 3. `native/` — raw FBX/OBJ/BLEND containers → measured records

Requires Blender (for `.blend` and container enumeration).

```bash
cd pipeline/native
python make_native_manifest2.py      # the worklist
bash index_native_all.sh             # measure the model files (one Blender session)
python run_blends.py                 # the .blend objects (one Blender process each)
python promote_native.py && python promote_blends.py   # -> _Agent_Files
cd ../.. && python pharos.py ingest  # imports the records
```

Chain 3 covers every top-level folder that `pharos.py ingest` does not
handle itself (the animation section, the scan folders, converted packs
and exported kits): in practice the `.blend` folders ingest asked about.
`indexer_skip_dirs` in the config leaves a folder out; to narrow a run
that was too broad, delete `<library>/_Agent_Files/native_models.jsonl`
first (a near-empty result never replaces a large live index on its
own). Both Blender chains measure through
`service/asset_service/blender_measure.py`, the same record shape
`pharos.py measure` produces without an engine.

## 4. `agent_index/` — the app's index files (pure Python)

```bash
cd pipeline/agent_index
python build_agent_index.py          # models.jsonl
python build_availability_catalog.py # availability.jsonl: owned vs on disk
```

`pharos.py ingest` runs `build_agent_index.py` and
`kitbash/build_kb3d_index.py` itself whenever converted packs or kits
exist; `build_availability_catalog.py` you run yourself. Every writer
refuses to let a near-empty result (fewer than 10
records, under half of the live index) replace a live index of 10 or
more; first builds and small libraries are written.

## Order for new downloads

Convert packs (1) and/or export kits (2) → enumerate natives (3) →
`python pharos.py ingest` → restart the server (a changed index file or
folder makes the importers run again).

## Standing rules

- Never modify anything under the library root except `Exports/` and
  `_Agent_Files/`.
- Manifest backups inside `Exports/` are `manifest.v1.bak`, never
  `*.json`.
- Verify with `verify_pack_export.py` after every engine run. Packs whose
  master materials expose no texture parameters verify with 0/N wiring:
  an authoring choice, not a failure (the verifier warns, never fails).
